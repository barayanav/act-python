## Primer ejercicio Nivel 01 — `task-cli`

Objetivo crear una aplicación de línea de comandos para gestionar tareas, con persistencia en JSON, tests y CI. Sin frameworks externos para la lógica principal; solo stdlib para el core.

### Requisitos funcionales

- Comandos mínimos
  - `add` añadir tarea con título, prioridad y fecha de creación.
  - `list` listar tareas, filtrar por estado o prioridad.
  - `done` marcar tarea como completada.
  - `delete` eliminar tarea.
  - `update` actualizar título o prioridad.
  - `stats` mostrar totales por estadoprioridad.
- IDs únicos.
- Estados `pending`, `done`.
- Prioridades `low`, `medium`, `high`.
- Timestamps en ISO 8601.
- Persistencia en archivo JSON configurable por variable de entorno o argumento.
- Salida legible por humanos y opción `--json` para salida machine-readable.
- Manejo de errores archivo corrupto, ID inexistente, argumentos inválidos.

### Requisitos técnicos

- Python 3.11+.
- Estructura `srctask_cli`.
- Tests con `pytest`.
- Linting y formateo con `ruff`.
- `pyproject.toml` con entrypoint para ejecutar como `task-cli`.
- GitHub Actions que corra `ruff` y `pytest` en cada pushPR.
- README con descripción, instalación, uso, ejemplos, decisiones técnicas y limitaciones.

### Restricciones

- No uses `click`, `typer`, `fire` ni similares para este primer ejercicio. Quiero que aprendas `argparse` y stdlib.
- No uses base de datos todavía.
- No uses pandas ni numpy.
- No metas Docker aún. Lo haremos después.

### Criterios de aceptación

- `pytest` pasa.
- `ruff check` pasa.
- El CLI funciona instalado con `pip install -e .`.
- El JSON se escribe de forma segura no debe corromperse si el proceso muere a mitad de escritura. Investiga escritura atómica.
- Los tests no dependen del archivo real del usuario; usan `tmp_path` o similar.
- El README permite a cualquiera ejecutar el proyecto sin preguntarte nada.

### Pistas y fuentes

- `argparse` documentación oficial de Python.
- `pathlib`, `json`, `datetime`, `dataclasses`, `typing`.
- `pytest` fixtures, `tmp_path`, `monkeypatch`, `capsys`.
- `ruff` documentación oficial.
- GitHub Actions workflow para Python.
- Busca “atomic file write python”, “pytest tmp_path”, “pyproject entry points”.

### Reto extra

- Añade subcomandos con `argparse` sin que el código se vuelva un monstruo.
- Añade tests de integración que ejecuten el CLI como subproceso.
- Añade un `Makefile` o `justfile` con tareas `install`, `test`, `lint`, `format`.
